# ADR 001 — local network/wallet set accepted; public compatibility pending

Date: October 2, 2026. Status: **accepted for isolated local integration (M2a); provisional for public Esmeralda (M2b pending)**.

Use Esmeralda for the intended beta and keep every public fixture separate from live evidence. The candidate released set is wallet **0.43.0**, template library **0.33.0**, test tooling **0.43.0**, Rust **1.97.1**, TS bindings **1.56.0**, and JS wallet client **1.24.0**. These are inspected published artifacts, not a declaration of interoperable network behavior. GitHub marks wallet v0.43.0 as a prerelease; it is an explicit preflight candidate and not approved as a release runtime.

The wallet guide advertised 0.43.0 when checked. Both candidate wallet containers report Esmeralda / byte 38. Both public indexers return the same network and current epoch. The library compiles the original ABI probe to an 89,766-byte WASM. The probe's Cargo.lock and pnpm's frontend lockfile are committed deliverables. Ten disposable WebAuthn/API-key checks pass, including `accounts:read` enforcement, expiry and revocation; see `wallet-auth.json` and the operation worksheet. Six real-engine tests now pass with pinned tooling, including faucet fee bootstrap, native concealed outputs/change, independent receiver spend and receipt behavior; see `docs/evidence/m2/funding-engine.md` for their limits. Human passkey setup, persistent authenticated restart, source-to-published-WASM linkage, wallet memo/scanning and public-network privacy/receiver spend remain unverified.

The wallet binary is pinned by SHA-256 `61ff7763cadf6236b58ee625c656e7aec55104ef910310a7281b746853c02749`, with a pinned Ubuntu 24.04 base. The source release hashes and npm package integrity values are retained in `docs/evidence/m2/release-research.json`. Frontend/browser/Rust base images are independently pinned by digest in `infra/docker/`. The research wallet's apt package resolution is not an immutable release package set; production approval requires the final runtime digest and vulnerability review.

Subsequent controlled local-wallet proof: [local-wallet.md](../evidence/m2/local-wallet.md) records successful actual faucet bootstrap, private transfer with memo recovery, independent receiver spending and restart recovery with persistent virtual passkeys. These resolve the corresponding local runtime questions. Human passkey/recovery, original template network publication/call, and public-network proof remain open; the candidate is still provisional.

Observed integration details affect the next implementation:

1. With the secret TOML config provided, runtime defaults selected a localhost indexer. Always set the verified indexer explicitly. `--network esme` alone did not establish actual network connectivity in this configuration.
2. Keyring override config deserializes a byte sequence, not a TOML string. The ignored initializer creates random separate per-wallet configs. A one-shot init service copies them into separately owned, read-only unlock volumes without passing passwords in process arguments. Named wallet data volumes are separate.
3. Authentication `none` still requires a scoped JWT for account/substate/settings reads. Unauthenticated `accounts.list` returns RPC 401. Read-only sessions are created in memory and never exported.
4. The released permission model uses structured CRUD capabilities, e.g. `{"Accounts":["Read",null]}` and `{"Substates":"Read"}`. The older `AccountInfo` permission example in the official guide is insufficient for this release. Use the generated types of the selected package and verify every scope at runtime.
5. The template macro rejects fixed-array ABI arguments. The original spike uses a `Vec<u8>` bounded to exactly 32 bytes. Freeze the full receipt ABI only after engine and live-call tests.
6. A fresh October 2 public faucet read confirms **empty**. The owner confirmed faucet-only funding; no alternate funding source or spend budget is authorized. Do not perform an L1 burn or silently fund with mainnet assets.

Current decision: accept this released set for isolated local integration. Native faucet funding, concealed transfer/memo detection, independent receiver spend, verified indexer inspection, original Wallet UI publication/create/read and persistent recovery have passed locally. The full application also executes actual encrypted submissions, receipts and private rewards with independent recipient scanning. Public Esmeralda acceptance still requires exact targets, measured fees and reviewed faucet-only operations. The M1 fixture tour remains a separately labelled demonstration.

October 2 funding-plan amendment: docs/funding-plan.md splits M2a local capability from M2b public proof. Start funding/test infrastructure and deterministic preparation now; proceed with local M3–M5 integration after M2a. Keep public beta deployment/live claims gated on M2b. Automated chain tests use faucet-origin funds; public-faucet availability must not block local tests. If the native RPC gate fails after funding, retain the compatible-wallet then bounded Rust adapter fallback. No feasibility gate has passed merely because the plan changed.

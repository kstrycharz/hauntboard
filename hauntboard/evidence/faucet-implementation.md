# Optional faucet — October 7, 2026

The privacy wallet offers Claim 500 test TARI after phrase confirmation. HAUNTBOARD_FAUCET_ENABLED defaults false in the application, public VPS and independent client; the local preview explicitly defaults true, and the current owner-authorized public beta enables it. Disabling it removes the wallet option and returns 404 from the dedicated submission endpoint, while create/recover/sync and ordinary posting remain available. It does not disable Tari's faucet for other clients.

The browser signs the builtin account/faucet transaction and retains **500 test TARI** in four native stealth outputs of 125 each. The released v0.45.0 builtin `take(account)` grants a fixed 1,000 TARI. The application pays an estimated, bounded claim fee from that grant and returns `500 TARI - maximum fee` through the builtin `deposit(bucket)` method in the same atomic transaction. Unused fee credit remains in the funding account and is included in the displayed total. Fees are estimated by Tari before a real signed submission; they are not hardcoded. Proofs, encryption and resource-address arguments use the pinned official Tari SDK/WASM. No server wallet, custody or recipient substitution is used for participant claims. The account/public owner key and sibling funding outputs are observable, so faucet-origin posting graphs can be correlated. Change stays quarantined after posting. A claim marker survives recovery while encrypted faucet outputs are discoverable.

The wallet now decrypts verified native output amounts locally and displays total balance, amount ready for posting, held change, and pending funds.

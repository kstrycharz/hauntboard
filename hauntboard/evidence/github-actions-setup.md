# GitHub Actions setup

Created the private repository https://github.com/kstrycharz/hauntboard and pushed the locally saved application, contract sources and workflows to main. The initial source commit is 6b783a2. GitHub recognizes the contract artifact, application gates and new manual Ubuntu deployment workflow.

The new workflow is dispatch-only on main, uses the repo-specific hauntboard-testnet runner label and serializes deployments without cancellation. It compiles and tests the contract, verifies source/WASM checksums, builds wallet/browser assets and the application image, then creates a new testnet board before staging/switching the app. Changed bytecode is published; identical compiled bytecode can reuse the existing template address. The live contract is independently verified on both Tari nodes. Failed live verification rolls back website configuration. Each GitHub run has a distinct persistent private deployment journal and a five-test-TARI fee budget. Private wallet state is excluded from artifacts.

Prepared server runner image: sha256:df194da3ff34b2563a7a7ba663c8187de72a7cdd46b38c3d65c76ff19fe94792. Official runner version: 2.338.0, Linux x64 archive SHA-256 af4b794c1bc41d73d40535e3fe092a39f9679cd8d965954c2aca25a05ca41d32. The archive was downloaded and verified in a container. Docker CLI and Compose compatibility were checked without a socket mount. Shell and JavaScript syntax checks passed for the new build/deploy/verification scripts.

Automatic approval review rejected starting a persistent runner with host Docker access and the full Hauntboard tree mounted, because repository workflows would gain ongoing administrator-equivalent control of the server. The owner was asked to approve that access. Planned mounts were narrowed to runner state/work folders and the app release folder, plus the Docker socket and read-only Docker tools. The runner has not been registered or started; the new deployment workflow has not yet run and the live app remains unchanged.

The first hosted application foundation job passed its Node tests and SDK build, then exposed a missing external Rust registry cache volume. The workflow now creates that volume before Rust adapter builds. The native contract artifact job started successfully and was compiling its engine tests at the last check. These are real GitHub runs; complete build/deployment acceptance remains pending.

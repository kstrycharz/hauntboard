# Native Tari L2 wallet import

Release 0.5.7 adds native Tari CipherSeed v2 imports to the existing Hauntboard phrase wallet. The browser calls released Tari Rust implementations through generated WASM bindings; it does not reinterpret native phrases as BIP39 entropy.

- `tari_common_types` 6.0.1: official mnemonic language detection, native word encoding, CipherSeed authentication/decryption.
- `tari_ootle_wallet_crypto` 0.45.0: account and view-key derivation using the selected account index.
- `tari_engine_types` 0.43.0: standard account component address derivation. The derived address matches the actual published operator account.
- `wasm-bindgen` / CLI 0.2.100: generated browser loader. Synchronous secret-buffer operations cannot interleave after initialization; temporary buffers are cleared.
- Wallet storage and device passwords retain the existing encrypted IndexedDB format.

The form supports automatic format detection, an optional original seed passphrase, an account index and an optional original receive-address check. A mismatched address is rejected before saving. Existing Hauntboard phrases retain their original keys and address. Recovery discovers the standard account, verifies its public-key owner before including its revealed native balance, and scans/decrypts native unspent outputs. Account funds are displayed separately from posting-ready stealth outputs and are never automatically transferred.

Compatibility fixtures are unfunded wallets generated by the official native Rust library. The browser tests compare both secret keys for accounts 0 and 7, with and without a seed passphrase, exercise mobile recovery, reject wrong seed passphrases and mismatched addresses, check that seed/password material is absent from network requests, and recover an existing Hauntboard identity with a changed device password. They do not claim faucet funds or publish messages.

Limits: this client uses Esmeralda, not mainnet or another testnet/reset. Standard native CipherSeed v2 is supported, alongside existing Hauntboard phrases; arbitrary custom wallet derivations, older CipherSeed versions, external signers and keys independently imported into another wallet are not reconstructed by that wallet's seed phrase. Recovery scans a bounded number of native outputs; it is not a complete multi-asset wallet history restore. Public posting privacy verification remains separate.

Public HTTPS verification passed after deployment in Chromium and Firefox on October 7 (America/New_York). See `native-wallet-import-chromium.json` and `native-wallet-import-firefox.json`: both record `NATIVE_L2_WALLET_IMPORT_PASSED` against the public Quick Tunnel URL. The health endpoint returned `ready`. The tunnel retained its original start time and was not restarted. No faucet claims, funds transfers or public posts were made by these import checks.

# Public Hauntboard contract candidate 0.2.0 / schema 4

The contract accepts mode 0 and opaque message bytes. Board/thread/page state retains full payloads, public title, random thread/post IDs, reply parents, page addresses/counts and epochs. There is no author public key field. The current browser can store public text or version-2 sealed bodies in those payloads, with public titles/categories. Encryption and invitation-key handling are client invariants; the contract does not enforce membership or secrecy. Existing schema-2/3 contracts and their history remain independent.

Posting and reading are public methods. Page writes still require the owning thread as caller. Retries compare nonce, parent and exact bytes without relying on a stable signer, so changed one-time keys can reconcile a logical post. Reusing a nonce with different bytes/parent fails. Someone observing an unconfirmed post can copy its exact public bytes/nonce and pay to publish it first; this produces the same logical content and does not establish authorship. Random IDs are not moderation credentials.

Limits remain 128 threads per board, 128 pages per thread, 16 posts per page, 2,048 posts per thread and 4,096 bytes per payload. The seven native tests include full-capacity, maximum-byte history/retry checks, invalid parents, conflicting thread retries and opaque-byte preservation using released template library 0.34.0 and engine 0.45.0.

The contract alone cannot hide transaction signatures, funding, fees, graphs or network connections. The standard client uses a native stealth fee input, one-time spend authorization and a fresh fee-receiver signature, omits the persistent wallet-owner signature and named account input, and quarantines change. The client can still be correlated through input ancestry, timing, messages and network observations. No complete anonymity claim is made.

Publishing this candidate and creating a board are separate transactions. Use the supported Esmeralda Wallet Web UI to estimate/publish the checksummed WASM under the approved account/budget, then call `Hauntboard::new(title)`. Record confirmed template/component/publication receipts. Do not set `posterPrivacyVerified` or `compatibilityVerified` until the native browser flow passes on the actual Tari-hosted Esmeralda providers. Native engine tests and localnet browser tests do not replace public proof.

The browser supports bounded native-output scanning and discovery from confirmed incoming receipts, with ownership checks performed locally. Change remains quarantined. Its encrypted ledger tracks up to 32 output records. Incoming fee outputs must exceed the initial 1 test-TARI simulation ceiling. The full reviewed fee, including the safety margin, is non-refundable on this path. Unknown submissions keep their exact signed envelope and are reconciled, never replaced by a new fee spend. See the current [privacy verification guide](../docs/privacy-verification.md) for source-versus-public evidence and the remaining funded Esmeralda gate.

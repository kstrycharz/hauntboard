# Tari phrase wallet

New wallets use standard Tari CipherSeed v2 phrases, generated by the official Rust implementation with browser cryptographic randomness. The birthday uses days since 2022-01-01, matching native wallets. The recovery form accepts native Tari L2 phrases and uses the released `tari_common_types` 6.0.1 decoder and `tari_ootle_wallet_crypto` 0.45.0 derivation. Native CipherSeed v2 supports its original optional seed passphrase and an account index (0 for the first account). All languages recognized by the official mnemonic decoder are accepted. An optional original receive address must match before encrypted storage is changed. The device password remains separate from the seed passphrase. The proprietary Hauntboard phrase option has been removed from participant onboarding. Its internal decoder remains only for retained deployment and validation records.

Recovery derives the standard built-in account component address with Tari's engine implementation and verifies its public-key owner before including revealed native balances. Stealth outputs are scanned and decrypted locally as before. Revealed account funds and posting-ready outputs are distinct; public account funds are not automatically spent. This is an Esmeralda client, so importing a seed does not transfer balances from a different network or network reset. Independently imported keys, external signers, custom wallet derivations and older CipherSeed versions are not covered by the native seed decoder. Do not describe this as universal recovery of arbitrary wallet formats.

The adapter now ships generated `wasm-bindgen` 0.2.100 browser bindings. Its exported buffer operations run synchronously after initialization and clear their buffers before returning keys. The browser stores the returned keys in encrypted IndexedDB. No phrase, original seed passphrase or device password is sent to the server. Compatibility tests generate unfunded fixtures using the official native Rust library, compare owner/view keys for accounts 0 and 7 with and without a seed passphrase, test mobile imports in Chromium and Firefox, reject wrong passphrases and mismatched addresses, and verify existing Hauntboard recovery. GitHub Actions runs these checks with the isolated chain.

The public privacy preview offers **Create wallet** and **Recover with seed phrase**. Creation shows 24 numbered words and requires confirmation that they have been saved before a post can be signed. Recovery needs those words and a device password of at least 12 characters. A fresh device can choose a different password without changing the wallet address. New records also bind their public wallet address into authenticated storage metadata, allowing the same phrase to reset a forgotten password on this browser without replacing another identity. Older records lacking that address binding require their current password here or recovery in a fresh browser profile. No wallet download or file upload is part of this flow.

Deprecated internal compatibility format `hauntboard-bip39-tari-v1` uses @scure/bip39 2.0.1, its English word list and 256 bits of browser-generated entropy. The phrase encodes that 32-byte entropy. The released `tari_ootle_wallet_crypto` 0.45.0 implementation derives the owner key with branch `account`, index 0, and the view key with branch `view_only_key`, index 0. The small Rust WASM adapter only exposes buffers and calls that implementation. This uses BIP39 entropy directly, not BIP39's password-derived 512-bit seed. It is **a Hauntboard recovery format, not the native Tari CipherSeed format**; do not import a phrase from another wallet assuming compatibility. The device password is local storage protection, not an optional mnemonic passphrase.

Owner/view keys, phrase and the coin ledger are password-encrypted in IndexedDB. Phrase/key/password material never belongs in requests, logs or screenshots. Closing the dialog removes displayed words; backgrounding and reloading lock the wallet. Browser cryptographic APIs require HTTPS or localhost; a plain HTTP LAN address can read the board but cannot create or unlock wallets.

A restored privacy wallet scans native unspent outputs, locally decrypts possible matches, then requires a verified substate before recording an owned output. Each sync examines at most 1,000 outputs in pages of 100; an incomplete scan continues on the next sync. Indexer lag may require another sync. At most 32 outputs are tracked. New posting change carries an encrypted Tari output memo so phrase recovery can keep that change quarantined. It is never automatically spent for a later post. The phrase restores keys, not another device's pending transaction intent or private local history. Indexer omission, network failure and public output graph/timing remain limitations.

Existing randomly generated wallets retain their original keys and encrypted records. They cannot acquire a seed phrase without changing identity; the UI explains this when asked to show words. Internal encrypted-record compatibility remains for old data, with no file controls exposed in the new wallet UI. Historical named-account demo tests use that compatibility because fresh-device account discovery is separate from native output recovery.

Build inside the pinned Rust container with `sh /workspace/hauntboard/wallet-recovery/build.sh`. The lockfile fixes dependencies. GitHub Actions builds this adapter before the application image and runs Chromium and Firefox phrase recovery tests. `tests/seed-wallet.mjs` funds a synthetic wallet on the isolated chain, publishes a post, restores on a fresh browser with a different password, checks change quarantine and publishes another post. Actual public Esmeralda fund recovery passed on October 7: `tests/public-wallet-recovery.mjs` restored the retained 500-token validation wallet in a fresh mobile browser with a new device password. It verified the same address, 500 test TARI ready for posting, a disabled already-claimed faucet, and no phrase or password in network requests. The recovery check made no new claims, transfers or posts. See [public recovery evidence](../evidence/esmeralda-public-wallet-recovery.json). Public posting privacy verification remains separate.
